# 2804 电机电流环实机接入与验证报告

## 1. 当前结论

本轮已经接通并验证以下链路：

```text
TIM1 20 kHz PWM/触发
        │
        ├── PE9/PE11/PE13 ── M0_IN_1/2/3 ── 三相功率级
        │
        └── ADC1 注入转换 ── PA0/PA1 ── M0_O1_CS/O2_CS
                                      │
                                      └── INA240A2 ×50 + 10 mΩ

ADC ISR ── 两相电流换算与 Ic 重构 ── Clarke/Park
        ── D/Q PI ── 逆 Park ── SVPWM ── TIM1 CCR1/2/3

FreeRTOS 高频任务 ── I2C1 DMA ── AS5600 Topic
                                  └── ADC ISR Peek
```

代码、主机测试、Debug/Release 编译、DAPLink 烧录和受限实机投运均已执行。电流采样、PWM、FOC 数学路径、安全关断和调试遥测能够工作，但目前没有进入最终 D/Q 电流闭环验证阶段。为隔离电流采样问题，当前启动流程已经临时改为限压开环速度验证；两档正反转测试都只能使转子小幅摆动，未形成连续旋转。

第一次验证的阻断点是转子未跟随完整电角度扫描。随后已经确认 AS5600 与 M0 电机属于同一根轴，手动转动时角度连续变化，电机也确实接在 M0 输出。新增三静态矢量诊断后进一步定位到：12 V 母线稳定，三个桥臂能够改变转子位置，但 PA0/PA1 两路相电流的符号和比例不符合正常三相关系。当前固件因此在进入扫描和电流环前返回 `SENSOR_ERROR` 并关闭输出。

## 3. 软件实现

### 3.1 控制核心

`foc_core` 已增加和验证：

- 电流传感器零偏校准入口和完成查询。
- 运行期转子方向与电角度零偏设置。
- 固定电角度开环电压模式，仅用于安全投运。
- ADC ISR 内同步电流读取、Clarke/Park、双 D/Q PI、逆 Park、SVPWM 和 duty 写入。
- 转子样本超时、非法数值、过流、驱动故障、目标超时和 duty 越界关断。
- 故障电流快照保留；功率关闭后的异步 ADC 数值标记为无效，避免误认为有效相电流。

### 3.2 电流传感器

双分流适配器当前实现：

```text
Ia = (ADC_A - offset_A) × 0.00161172 × direction_A
Ib = (ADC_B - offset_B) × 0.00161172 × direction_B
Ic = -Ia - Ib
```

实机发现不能在门极驱动关闭时测零偏。关闭输出时得到的 ADC 基线与驱动使能、三相 50% 中性占空比时的工作基线不同，尤其 B 路相差约 670 count，足以制造约 1 A 的假电流并触发过流。

当前流程会先写入三相 50% duty，再使能功率级，并在零线电压条件下累计 4096 个同步样本。最近两轮校准结果约为：

```text
offset_A = 1853 count
offset_B = 2696 count
```

该阶段只有共模开关，没有施加线间电压；校准结束前不会进入控制状态。

官方原理图显示 M0 两路 INA240 的输入极性不同；官方 SimpleFOC 例程也固定执行 `current_sense0.gain_b *= -1`。因此当前板级配置固定为：

```text
PA0 / M0_OUT1_CS：direction_A = +1
PA1 / M0_OUT2_CS：direction_B = -1
```

不再根据一个静态矢量自动猜测极性。

### 3.3 三相输出

旧工程的已验证输出代码采用反向逻辑相映射。当前工程已按它保持一致：

```text
逻辑相 A → TIM1_CH3 → PE13 → M0_IN_3
逻辑相 B → TIM1_CH2 → PE11 → M0_IN_2
逻辑相 C → TIM1_CH1 → PE9  → M0_IN_1
```

TIM1 采用 20 kHz 中心对齐 PWM。ADC1 注入转换由 TIM1 同步触发，实测 ADC ISR 约为每秒 20000 次。完整开环输出目前按 2:1 分频以约 10 kHz 运行，与旧工程 TIM1 更新回调的实际频率一致。

输出关闭时同时执行：

- `MOTOR_EN` 拉低。
- TIM1 `BDTR.MOE` 清零。
- CCR1/CCR2/CCR3 恢复到 2100，即 50% 中性 duty。

## 4. 自动投运流程

原电流环投运流程包含三静态矢量、电角度扫描和 D/Q 电流环验证。由于三静态矢量的电流关系尚未通过，当前 Debug 固件暂时改为不进入电流环的开环速度验证：

1. 等待模拟前端稳定。
2. 在中性 PWM 状态采集 4096 个电流零偏样本。
3. 等待 AS5600 样本有效且母线位于 9–15 V。
4. 以零电压目标使能功率级，在 500 ms 内把 Q 轴电压缓升到 3.0 V。
5. 用 3 s 加速、2 s 恒速、3 s 减速的梯形曲线正向运行，目标机械角速度为 10 rad/s；7 极对对应峰值电角速度 70 rad/s。
6. 关闭输出并等待 500 ms。
7. 以相同电压和梯形速度曲线反向运行。
8. 检查两个方向的机械位移是否均超过 0.25 rad 且符号相反。
9. 无论成功或失败，结束后都关闭功率输出。

当前开环速度模式不使用电流反馈和编码器电角度，只使用 AS5600 记录实际机械位移。同步电流采样仍以 20 kHz 保留为 1.8 A 过流保护，但不会进入 PI 电流闭环。当前完整控制采用 2:1 分频的 10 kHz ISR 路径；任务发布参考角度和瞬时速度，ISR 按微秒时间连续外推电角度，避免 10 ms 目标更新造成阶梯磁场。

## 5. 实机验证结果

### 5.1 已通过

- AS5600 在 I2C1 上持续采样，序号递增；重新上电后的诊断累计出现 2 次瞬时通信错误，连续错误计数最终回到 0，没有阻断本轮诊断。
- ADC1 注入中断和 20 kHz 控制 ISR 连续运行。
- 中性 PWM 零偏校准稳定完成。
- 3 V 固定矢量产生了可测相电流，并能改变转子机械角。
- TIM1 三路 PWM 采用 M0_IN_1/2/3 直连配置，控制 ISR 持续运行。
- 第一轮完整诊断未出现过流、NaN、输出范围或驱动 Fault。
- Debug 烧录、校验与复位成功。
- 最终安全寄存器状态：

```text
GPIOE ODR bit 5 = 0       MOTOR_EN 关闭
TIM1 BDTR = 0x2000        MOE bit 15 = 0
TIM1 CCR1/2/3 = 2100      中性 duty
FOC state = READY
fault_flags = 0
```

### 5.2 未通过

两个静态电角度点在 1 V 下的机械位移约为 0.009 rad；提高到商家建议的 3 V 后约为 0.0169 rad，仍远低于 90° 电角度对应的理论机械位移：

```text
(π / 2) / 7 = 0.2244 rad = 12.86°
```

随后采用商家/旧工程风格的完整电角度扫描：

```text
起始机械角 = 1.44501 rad
结束机械角 = 1.44654 rad
实际位移   = 0.00153 rad = 0.088°
理论位移   = 2π / 7 = 0.8976 rad = 51.43°
```

因此程序停在 `FAILED / ROTOR_ALIGNMENT_FAILED`。当次控制 ISR 序号约为 131434，证明扫描命令和同步控制持续执行，而不是任务或 ADC 中断中途停止。

### 5.3 三静态矢量诊断

人工确认结果：

- 手动转动 M0 电机时，AS5600 的 `angle/raw` 连续变化。
- 扫描期间电机有轻微跳动。
- 电机确定接在 M0 功率输出。

诊断固件在 0°、120°、240° 三个电角度分别施加 3 V。以下电流已按官方板级极性 `A 正、B 负` 统一：

| 电压矢量 | Ia | Ib | 重构 Ic | 机械角 |
| --- | ---: | ---: | ---: | ---: |
| 0° | +0.392 A | +0.025 A | -0.417 A | 3.240 rad |
| 120° | +0.297 A | +0.396 A | -0.693 A | 3.321 rad |
| 240° | +0.425 A | +0.022 A | -0.447 A | 3.399 rad |

对应的理想三相关系应近似为：

```text
0°：   Ia 为正且主导，Ib ≈ Ic ≈ -Ia / 2
120°： Ib 为正且主导，Ia ≈ Ic ≈ -Ib / 2
240°： Ic 为正且主导，Ia ≈ Ib ≈ -Ic / 2
```

实测中 A 路三个点始终为正，B 路在 0° 和 240° 近乎为零，因此不满足任意简单的三相相序置换。与此同时，机械角随三个矢量连续增加，说明功率级并非完全没有输出。

ADC3 同期测得母线约为 `12.428 V`，诊断期间最小值也为约 `12.428 V`，可以排除 12 V 电源在这次轻载测试中明显跌落。

诊断结束后的硬件状态为：

```text
MOTOR_EN = 0
TIM1 BDTR.MOE = 0
TIM1 CCR1/CCR2/CCR3 = 2100
commissioning = FAILED / SENSOR_ERROR
```

AS5600 重新上电并从调试口复位 MCU 后，固定板级极性版本已经完整执行诊断。最终累计 `bus_update_error_count` 为 2、`consecutive_bus_error_count` 为 0，转子传感器初始化成功且通信已经恢复；调试器第一次暂停时恰好落在一次 I2C 地址等待函数内，并不代表总线仍然卡死。新的三矢量结果仍未通过联合检查，最终状态稳定为 `FAILED / SENSOR_ERROR`。这说明阻断项已经不再是 AS5600 通信，而是三相输出与两路电流采样之间的硬件关系。

### 5.4 开环速度验证

在绕过三矢量电流一致性门槛后，执行了多档限压、限速、自动关断的正反向开环测试：

| 测试 | Q 轴电压 | 控制路径 | 目标速度 | 正向机械位移 | 反向机械位移 | 结果 |
| --- | ---: | --- | ---: | ---: | ---: | --- |
| 第一档 | 1.5 V | 20 kHz ISR | 6.283 rad/s 电角 | -0.035 rad | +0.012 rad | 未连续旋转 |
| 第二档 | 2.0 V | 20 kHz ISR | 1.000 rad/s 电角 | +0.054 rad | -0.075 rad | 未连续旋转 |
| 第三档 | 3.0 V | 10 ms 阶梯目标、20 kHz ISR | 12 rad/s 机械 | +0.052 rad | -0.069 rad | 目标更新过粗，结果不作为控制频率结论 |
| 第四档 | 3.0 V | 1 kHz FreeRTOS 任务 | 12 rad/s 机械 | -0.091 rad | +0.040 rad | 未连续旋转 |
| 第五档 | 3.0 V | 1 kHz 分频 ISR | 12 rad/s 机械 | -0.094 rad | +0.041 rad | 未连续旋转 |
| 第六档 | 3.0 V | 旧工程相映射、10 kHz ISR | 10 rad/s 机械 | +0.061 rad | +0.005 rad | 未连续旋转 |

第五档测试时母线约为 12.30 V，`fault_flags=0`，AS5600 无累计或连续通信错误。20 kHz ADC 中断累计约 340463 次，20:1 分频后的完整控制累计 17023 次，与两段共约 17 s 的 1 kHz 控制吻合。1 kHz RTOS 任务与 1 kHz ISR 的机械位移几乎一致，因此可以排除“20 kHz 控制计算来不及”是震颤的主要原因。结果仍为 `FAILED / ROTOR_ALIGNMENT_FAILED`，结束后的 `MOTOR_EN=0`、TIM1 `MOE=0`、三路 CCR 均为 2100。

第六档运行时，SWD 在不停止目标的情况下连续读取了 TIM1 CCR。三路比较值均在约 1200～3000 之间连续轮换，`MOTOR_EN` 同期为高；结束后 ADC ISR 累计约 340029 次，10 kHz 完整控制累计约 170014 次且 `fault_flags=0`。这证明参考角推进、逆 Park、SVPWM、三路 CCR 写入和功率使能软件链均持续运行。

### 5.5 旧工程原始固件 A/B 对照

为排除新框架造成的差异，在独立构建目录中直接使用 `~/embedded_project/oled_imu_foc` 当前工作树的原始 CubeMX 代码、原始 `foc_motor`、原始事件循环以及其未提交的 `3 V / velocity_openloop / 10 rad/s` 参数，使用 GCC 生成并烧录了对照固件。旧工程源码和仓库未被修改。

旧固件在本次硬件状态下同样未通过原有 `align()`。调试器读到：

```text
controller_type = velocity_openloop
voltage_power_supply = 12 V
voltage_limit = 3 V
sensor_direction = UNKNOWN
controller.is_enable = false
```

`is_enable=false` 是旧代码在 `align()` 发现编码器机械位移不足后主动调用 `disable()` 的结果。旧固件的对齐过程直接写三相 PWM，不依赖新工程的 RTOS、Topic、ADC 控制回调或新 SVPWM 实现，因此这次 A/B 结果表明：旧工程历史上确实能够运行，但在当前上电和连接状态下也不能复现连续转动，主因已不再指向新 FOC 框架。

人工发现并重新检查一处松动接线后，再次进行了完整 A/B 测试。当前固件仍得到正向约 `0.0644 rad`、反向约 `0.00614 rad`，母线约 `12.375 V`，且 FOC、I2C 均无故障。随后再次烧录旧工程原始固件，其 `align()` 仍返回失败，`sensor_direction` 仍为 `UNKNOWN`，尚未进入开环速度事件。说明已发现的松线不是唯一阻断项，或该连接修复后对应信号仍未可靠到达功率级。

六步静态测试后再次从旧工程当前工作树重新执行完整 GCC 构建和烧录。旧工程当时的未提交目标为 `velocity_openloop=1.0 rad/s`，其余为 12 V 母线、6 V 速度开环限压、3 V 对齐电压和 7 极对。通过硬件断点直接读取原版 `align()` 的正扫、反扫终点：

```text
mid_angle = 5.32598162 rad
end_angle = 5.32291365 rad
abs(mid_angle - end_angle) = 0.00306797 rad
```

该位移只有两个 AS5600 count，远低于旧代码要求的 `0.02 rad`，所以旧工程再次得到 `sensor_direction=UNKNOWN`、`controller.is_enable=false`。AS5600 在两个断点分别累计 99 和 199 个有效样本，说明失败并非编码器没有刷新。原版速度开环因此没有被执行，驱动使能脚最终保持低电平。

随后不修改旧工程源码，通过调试器在 `align()` 失败后强制设置控制器使能和 `MOTOR_EN`，直接执行原版 `velocity_openloop=1.0 rad/s`。测试期间读到：

```text
controller.is_enable = true
Uq = 6 V
shaft_angle = 1.5717 rad
electrical_angle = 11.0021 rad
CCR1/CCR2/CCR3 = 515/544/3683
```

这证明旧工程已经越过对齐门槛，开环参考角和三路 SVPWM 比较值持续变化。AS5600 累计机械角仅从 `5.32445 rad` 变化到 `5.27996 rad`，总位移约 `-0.04449 rad`，仍未形成连续旋转。测试结束后已强制设置 `MOTOR_EN=0`、`controller.is_enable=false`、`Uq=Ud=0`，并把三路 CCR 恢复为中性值。

### 5.6 最简任务与中断开环对照

为继续排除框架干扰，新增了临时 `debug/foc_open_loop_debug`。启动入口暂时不创建 MPU6050、FOC、AS5600、ADC 和 UART 调试任务，由该模块直接独占 TIM1 与 `MOTOR_EN`。测试使用 12 V 母线、3 V 正弦调制、7 极对和 10 rad/s 机械速度，顺序为：

1. 固定电角度吸合 1 s。
2. RTOS 任务以 1 ms 周期正向运行 5 s。
3. 关闭输出并等待 2 s。
4. 固定电角度吸合 1 s。
5. TIM1 CC4 中断以约 10 kHz 反向运行 5 s。
6. 关闭 `MOTOR_EN`、MOE 并恢复三相中性占空比。

调试器最终读到：

```text
stage = COMPLETE
task_update_count = 5000
interrupt_event_count = 120029
interrupt_update_count = 60014
MOTOR_EN = 0
TIM1 MOE = 0
CCR1/CCR2/CCR3 = 2100
```

这证明完全绕过原 FOC 数据流后，RTOS 任务和硬件中断两种开环输出路径都按预期完成。该版本刻意不读取 AS5600，因此是否形成连续正反转需要结合人工观察确认。

人工观察确认两段均未形成连续旋转，只表现为小幅高频原地摆动。随后把目标机械速度从正反向 `10 rad/s` 降到 `1 rad/s`，同时修正了对齐矢量会被使能函数的中性占空比覆盖的问题。低速测试仍然只表现为慢速往复摆动，因此目标速度阶跃和缺少预对齐不是主因。

### 5.7 六步静态矢量与旁路角度观测

为在没有示波器和逻辑分析仪的条件下继续诊断，临时开环模块增加了只读 AS5600 旁路观察任务。AS5600 不参与电角度生成，控制路径仍然只依赖时间积分。固件依次保持 `0°`、`60°`、`120°`、`180°`、`240°`、`300°` 六个电角度，每个位置保持 1.5 s，然后执行 `+1 rad/s` RTOS 开环和 `-1 rad/s` 10 kHz ISR 开环。

调试器读取的六个静态终点机械角为：

```text
4.270, 4.149, 4.121, 4.169, 4.255, 4.296 rad
```

相邻变化量为：

```text
-0.121, -0.028, +0.048, +0.086, +0.041 rad
```

7 极对电机在电压矢量每次单向前进 `60°` 电角度时，正常跟随的机械角步长应约为：

```text
(π / 3) / 7 = 0.1496 rad = 8.57°
```

实测角度先反向、后正向，并未形成六个同方向递进的位置。RTOS 慢速段只从 `4.272 rad` 变化到 `4.296 rad`，ISR 反向段只从 `4.272 rad` 变化到 `4.203 rad`。这与人工观察的慢速往复摆动一致。

旁路观察期间 AS5600 累计取得 24398 个样本，通信错误为 0；RTOS 控制更新 8000 次，ISR 控制更新 90021 次。测试结束后 `MOTOR_EN=0`、TIM1 `MOE=0`，三路 CCR 均恢复为 2100。

## 6. 当前阻断项与下一步

3 V 开环在 RTOS 任务、1 kHz ISR、10 kHz ISR 和旧工程原始固件中都没有连续转动，可以排除控制执行上下文、20 kHz 计算负载以及新旧 SVPWM 数学差异。下一步按以下顺序排查：

1. 用示波器或逻辑分析仪检查 PE9/PE11/PE13 是否均有 20 kHz PWM，三路占空比是否随开环电角度连续轮换。
2. 在驱动板输入端 M0_IN_1/2/3 再测一次，排除自制转接板连接或接触问题。
3. 若三路输入正常，再检查 M0 三个功率输出端的相间 PWM 电压，确认三个半桥都能响应。
4. 用示波器观察 PA0/PA1：输出关闭时约为各自零偏；中性 PWM 时不应出现数百 count 的直流偏移；旋转磁场运行时两路信号应跨越零偏变化。
5. 只有开环速度能够稳定旋转后，才进入带编码器角度的电压力矩模式；相电流关系通过后再恢复 D/Q 电流环验证。

六步静态锁定位置扫描已经完成，并确认旋转磁场在机械端退化为往复磁场。结合旧工程原始固件同样失败，可以把主因进一步收敛到当前硬件链路：至少一路 PWM 信号未可靠到达驱动板、一个半桥未正常响应，或电机三相连接仍存在接触问题。当前最值得优先检查的是转接板到 `M0_IN_1/2/3` 的连续性、M0 三个半桥响应以及电机三相插头；相电流采样异常作为独立问题保留。现有结果不支持继续通过修改控制频率、任务上下文、相序或软件零偏来绕过问题。
