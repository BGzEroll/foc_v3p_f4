## 2. 工程修改

### 2.1 自动生成烧录产物

在顶层 `CMakeLists.txt` 中给 `project` 增加 POST_BUILD 命令。成功链接 ELF 后自动生成：

```text
project.elf
project.hex
project.bin
project.map
```

构建结束时自动运行 `arm-none-eabi-size` 输出程序尺寸。

### 2.2 增加一键烧录目标

顶层 CMake 增加 `flash` 目标，参数为：

```text
interface/cmsis-dap.cfg
transport select swd
target/stm32f4x.cfg
adapter speed 1000
program <project.elf> verify reset exit
```

日常烧录命令：

```bash
cmake --build --preset Debug --target flash
```

`flash` 依赖 `project`，烧录前会自动确保固件为最新版本。

### 2.3 忽略构建目录

新增 `.gitignore`，忽略 `/build/`。

### 2.4 链接脚本

本次没有修改 `STM32F407xx_FLASH.ld`。Debian 官方 GNU Arm GCC 14.2.1 / binutils 2.44 原生支持 CubeMX 生成的 `(READONLY)` 输出段语法，初始链接脚本可直接成功链接。

## 7. 日常使用

Debug 编译：

```bash
cmake --preset Debug
cmake --build --preset Debug --parallel
```

Debug 编译并烧录：

```bash
cmake --build --preset Debug --target flash
```

Release 编译：

```bash
cmake --preset Release
cmake --build --preset Release --parallel
```

将 SWD 时钟降到 100 kHz：

```bash
cmake --preset Debug -DOPENOCD_ADAPTER_SPEED=100
cmake --build --preset Debug --target flash
```

## 8. 根目录一键脚本

工程根目录提供两个可执行脚本：

```text
build_flash_debug.sh
build_flash_release.sh
```

Debug 一键配置、编译、烧录、校验和复位：

```bash
./build_flash_debug.sh
```

Release 一键配置、编译、烧录、校验和复位：

```bash
./build_flash_release.sh
```

脚本会固定使用 `/usr/bin:/bin` 中的 Debian 官方工具，检查 CMake、Ninja、GNU Arm GCC、OpenOCD 和 `lsusb`，并在烧录前确认 USB 设备 `0416:5051` 已连接。两个脚本均已在开发板上实际运行，输出 `Programming Finished`、`Verified OK` 和 `Resetting Target`。
