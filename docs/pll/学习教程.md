# 从零学习反电势观测器与 PLL：本项目的完整实验流程

本次目标是 2804 电机、7 极对、12 V 母线、STM32F407 上的无感 FOC。AS5600 用于带动电机和核对估算值。本次 MATLAB 与 Simulink 的算法仿真通过，板上实时采样、旁路估算和 RTT 已跑通；**实机角度估算尚未可靠锁定，无感控制未切换，不能作为已经调好无感 FOC 的成品使用。** 具体数据见 [实机记录](实机记录.md)。

建议先读第 1～5 节，再运行第 6 节的 MATLAB 实验，随后对照第 7～10 节看固件。这里所有速度若无特别说明，都指**电角速度，单位 rad/s**。

## 1. FOC 为什么需要转子角度

三相电流经过 Clarke 变换变成固定在定子上的两个分量：

\[
i_\alpha=i_A,\qquad i_\beta=(i_A+2i_B)/\sqrt3,\qquad i_A+i_B+i_C=0.
\]

Park 变换再把它们投影到跟着转子转动的 d/q 坐标：

\[
i_d=i_\alpha\cos\theta_e+i_\beta\sin\theta_e,
\qquad i_q=-i_\alpha\sin\theta_e+i_\beta\cos\theta_e.
\]

通常 d 轴用于磁通，q 轴用于转矩。角度错了，控制器就把一部分电流送到了不希望的方向，所以“速度看起来差不多”不足以证明可以接管 FOC。

本电机机械转一圈，电角度转 7 圈：

\[
\theta_e=\operatorname{wrap}(7\theta_m+\theta_0),\qquad
\omega_e=7\omega_m,\qquad
\mathrm{rpm}=\omega_e\frac{60}{2\pi\cdot7}.
\]

例如 100 rad/s 电角速度约为 136.4 rpm 机械转速，180 rad/s 约为 245.6 rpm。工程里的编码器方向、机械零点和电角度零点还要一起纳入，不能简单地把 AS5600 原始角度乘以 7 就作比较。

## 2. 无感角度从哪里来

本实验采用表贴式永磁同步电机的简化模型，假定 \(L_d=L_q=L\)：

\[
v_\alpha=Ri_\alpha+L\dot i_\alpha+e_\alpha,\qquad
v_\beta=Ri_\beta+L\dot i_\beta+e_\beta.
\]

旋转永磁体产生反电势：

\[
e_\alpha=-\psi_f\omega_e\sin\theta_e,\qquad
e_\beta=\psi_f\omega_e\cos\theta_e.
\]

因此得到反电势向量，就有机会得到转子角度。直接计算 \(e=v-Ri-L\dot i\) 很直观，但电流差分会放大 ADC 噪声，本实验使用观测器来估计 \(e\)。

关键限制是 \(|e|=\psi_f|\omega_e|\)：停转时反电势消失，低速时容易被电流零偏、死区和电压误差淹没。单靠这个方法无法从静止可靠知道转子角度。完整产品还需要开环启动或其他低速位置估计方案；本次实现的是**编码器辅助启动、旁路验证、满足条件后有限时长试验接管**，没有实现无编码器冷启动。

工程已有的 AS5600 速度平滑 PLL 使用的是“编码器测得的角度”。本次新增的是“反电势观测器提供角度”的 PLL。二者原理有相似处，信号来源和适用条件不同。

## 3. 观测器：用模型预测，再用测量纠正

每一轴维护两个内部状态：估计电流 \(\hat i\) 和估计反电势 \(\hat e\)：

\[
r=i-\hat i,
\qquad \dot{\hat i}=\frac{v-R\hat i-\hat e}{L}+k_i r,
\qquad \dot{\hat e}=-k_e r.
\]

电流测量大于预测时，模型必须纠正；反电势估计的负反馈符号来自电机方程里 \(-e/L\) 对电流变化的作用。将误差方程展开，其特征多项式为：

\[
s^2+(R/L+k_i)s+k_e/L.
\]

令它等于期望的二阶多项式 \(s^2+2\zeta_o\omega_o s+\omega_o^2\)，得到：

\[
k_i=2\zeta_o\omega_o-R/L,\qquad k_e=L\omega_o^2.
\]

本实验参数：\(R=2.55\ \Omega\)、\(L=0.00086\ H\)、\(\omega_o=6000\ rad/s\)、\(\zeta_o=1\)、\(T_s=50\ \mu s\)。R、L、磁链均沿用项目配置，**没有完成对这台实物电机的参数辨识**，不是已经测准的数值。

代码用前向 Euler 离散化，例如：

\[
\hat i[n+1]=\hat i[n]+T_s\left((v[n]-R\hat i[n]-\hat e[n])/L+k_i r[n]\right).
\]

`bemf_pll_step()` 的输入约定是：`i[n]` 为当前时刻电流，`v[n]` 为接下来一个采样区间的平均电压；先输出当前状态估计，再推进到下一时刻。这个时序约定在仿真和实机接线时都要检查。

观测器并非无限快，它会使估计的正弦反电势产生相位延迟。这里按**实际 Euler 离散模型**做稳态相位补偿：

\[
s_d=(e^{j\omega T_s}-1)/T_s,\qquad
H(z)=\frac{\omega_o^2}{s_d^2+2\zeta_o\omega_o s_d+\omega_o^2}.
\]

角度加上分母的相角以补偿这个模型的延迟。它不包含逆变器死区、PWM 更新延迟、ADC 放大器延迟、编码器 I²C 延迟，也不能纠正参数失配或接线错误。

## 4. PLL 到底在做什么

PLL 是一个持续追踪相位的反馈环。它有自己的角度和速度，根据“输入相位减预测相位”的误差纠正自己。可以把它想成跟着另一个指针转动：落后就加快一点，超前就放慢一点。

先把反电势变成输入相位。设转向 \(d=+1\) 或 \(-1\)：

\[
\theta_{emf}=\operatorname{atan2}(-d\hat e_\alpha,d\hat e_\beta).
\]

反转时反电势整体变号，如果不加入 d，结果会差 \(\pi\)。本实验旁路阶段借助编码器的速度确定转向；完全无感启动时应由启动策略提供转向，这一部分还未实现。

`wrap()` 把角度约束在 \([-\pi,\pi)\)。例如一个角度接近 +π、另一个接近 −π，实际只有很小的差，不能用普通减法得到接近 2π 的假误差。

代码中的离散更新是：

\[
\theta_p[n]=\operatorname{wrap}(\hat\theta[n-1]+T_s\hat\omega[n-1]),
\]
\[
\varepsilon[n]=\operatorname{wrap}(\theta_{emf,comp}[n]-\theta_p[n]),
\]
\[
\hat\omega[n]=\operatorname{clamp}(\hat\omega[n-1]+K_iT_s\varepsilon[n]),
\qquad
\hat\theta[n]=\operatorname{wrap}(\theta_p[n]+K_pT_s\varepsilon[n]).
\]

这里速度输出取积分状态，角度更新另外包含比例纠正。对应连续时间二阶设计：

\[
K_p=2\zeta_p\omega_p,\qquad K_i=\omega_p^2.
\]

阻尼 \(\zeta_p=0.7071\)。通用算法默认 \(\omega_p=200\ rad/s\)，板上实验选 60 rad/s 来减小噪声；二者分别约为 31.8 Hz 和 9.55 Hz 的自然频率，不能把 rad/s 参数直接叫作 Hz 带宽。自然频率也不严格等于闭环 −3 dB 带宽。

增大 \(\omega_p\) 通常追踪更快，也会把更多输入噪声送到估计速度里；降低它不会修复反电势模型里的固定角度偏差。

## 5. `valid`、`locked` 与“能接管 FOC”是三件事

`valid=1` 表示当前估计的反电势幅值至少 0.08 V，可以进行相位计算。`locked=1` 还要求内部相位误差小于 0.15 rad、沿指定转向的速度至少 30 rad/s、速度未饱和，并连续保持 50 ms。

30 rad/s 电角速度约为 40.9 rpm 机械转速。这是本实验的判定门槛，不代表该硬件已经验证可以在此速度运行。

停止的电机也可能由于 \(v-Ri\) 模型残差估计出一条非零的“反电势”。内部 PLL 可以跟住这个假向量，所以后加了速度门槛以排除明显的静止误锁。**速度门槛不能识别所有假信号。** R 偏差也能让内部 PLL 显示锁定但真实角度有偏差，仿真的 R+20% 场景就是例子。

板上切换还要求：正常电流映射；编码器参考有效；电角速度大于 30 rad/s；相对编码器角度误差小于 0.20 rad（约 11.46°）；速度误差小于参考值的 20%；母线 10～14 V；以上条件连续满足 500 ms。只有收到 `request=1` 才尝试接管。这是带编码器的实验门槛，不是对全工作范围的稳定性证明。

接管后反馈函数提供下一采样时刻的 PLL 预测角度和电角速度。出现估计无效、内部失锁、超过 75 μs 的周期，或达到 200000 个采样（正常 20 kHz 下 10 s），会锁存故障并关断输出。母线、电流的既有保护仍在运行；编码器超时关断在有感反馈链路中生效，接管后仅作参考的编码器读数失效不会直接宣布 PLL 失效，这一行为尚未实机验证。这版需要 AS5600 完成初始化、对齐、编码器启动和交接门槛判断，不能拔掉编码器宣称已经全无感。

建议按这个顺序看：

1. `forward_step`：1 s 时电角速度 100→180 rad/s；比较输入与估计角度、速度。
2. `reverse_step`：检查反转方向和 π 修正。
3. `current_noise`：电流加入 1.6 mA RMS 噪声、电压加入 10 mV RMS 噪声，观察速度抖动。
4. `R_plus20pct`：观测器 R 比真实 R 大 20%；观察**锁定不等于真实角度准确**。
5. `L_plus20pct`：本组轨迹里的 L 失配影响较小，不能推广成所有工况都不敏感。
6. `low_speed`：10 rad/s 时反电势约 0.035 V，低于幅值门槛，应拒绝锁定。
7. `emf_loss`：1 s 后停转，应在残余状态衰减后失效，而不是保留旧速度。
8. 看 `bandwidth_sweep.csv`：60、200、500 rad/s 的自然频率怎样影响同一噪声输入下的速度标准差。

摘要的角度 RMS 只在已排除启动/阶跃过渡的窗口中计算，且仅统计 `valid` 点。低速的 NaN 意味着没有可接受的估算点，不是 0 误差；失电势场景全窗口的锁定比例包括停转前的一段，不表示停转后还锁着。

| 文件 | 职责 |

| `user_lib/drivers/foc/sensorless/pll_experiment.c/.h` | 旁路采样、AS5600 比较、试验门槛与定时停止 |
| `user_lib/third-parts/SguanFOC/wrapper/sguan_foc_wrapper.cpp` | 20 kHz 环接入、电压重建、运行耗时与关断 |
| `user_lib/third-parts/SguanFOC/SguanFOC.c` | 接管状态时从 PLL 取控制角度/速度 |
| `user_lib/devices/foc_dev.cpp` | ADC/PWM 启动、校准触发修复、待机/手动启动 |
| `user_lib/debug/pll_rtt.cpp/.h` | 任务中 10 Hz RTT 状态输出 |
| `tests/pll/` | 算法与实验保护主机测试 |
| `scripts/pll/` | MATLAB、Simulink、SWD 采集与 RTT 工具 |

本项目 TIM8 中心对齐，计数周期参数 4200、时钟 168 MHz，理论周期为 \(2\times4200/168\mathrm{MHz}=50\ \mu s\)。但**理论 PWM 频率不保证高速代码真的每 50 μs 跑一次**。本次 Debug 运行超过预算，一度实际只每 100 μs 更新一次，固定使用 50 μs 的估算器速度就出现约 2 倍偏差。

现在推荐 `PLLRelease`：应用代码 `-O2 -g3`，保留离线解析结构地址所需的符号，开启 RTT；Cube 库仍按工具链 Release 的选项构建，关键 ADC/队列等路径另外指定 `-O2`。只设置 `CMAKE_C_FLAGS_RELEASE` 不足以覆盖该工程工具链中的全部选项，所以增加了目标级选项。普通 `Release` 没有打开符号/RTT 选项，不推荐拿它给 Python 诊断工具配地址。

ADC2 由 TIM8 CC4 触发。实机发现原代码在启动 PWM 后清 MOE，电流零偏校准收不到样本。修复为：校准时 `MOTOR_EN=0`，保留 MOE 与三个中性占空比，使 ADC 触发持续；校准结束才进入既有对齐流程。**MOE=1 不等于电机已使能，必须同时看驱动的 MOTOR_EN。**

### 电压输入不是直接测得的电机端电压

算法需要电压、电流处在相同的物理 αβ 坐标里。代码使用最终限幅后的占空比和母线电压重建平均电压：

\[
v_\alpha=p_{pwm}V_{bus}(2d_U-d_V-d_W)/3,
\quad v_\beta=p_{pwm}V_{bus}(d_V-d_W)/\sqrt3.
\]

三相公共偏置被消去；还按工程 PWM 方向和电机换相约定映射坐标。本板逻辑 U/V/W 对应 TIM8 CH3/CH2/CH1；电流 ADC 的现有配置是 A/C 两相、方向 +1/−1。

**这些映射沿用软件配置，尚未用示波器/独立电流测量完成物理确认。** 重建电压没有补偿 MOSFET 压降与死区，PWM 比较值预装载何时生效也需要与 ADC 采样位置核实。低反电势下这些误差很重要。旁路 `mapping=1` 只把观测器看到的 A/C 交换作诊断，不改变控制器电流反馈，也不代表完成了接线校准；此模式禁止接管。


这个目标会 program、verify、reset。**重置之后会执行既有的约 1 秒静态转子对齐，再经过约 800 ms 等待，之后默认关闭持续运行输出。** 电机可能在对齐时动作。默认 `PLL_AUTO_RUN_ENCODER=OFF`；不要把“默认待机”理解为从上电开始绝对不动。

烧录完成后重新运行 OpenOCD，另一个终端执行：

```bash
python3 scripts/pll/board_status.py
python3 scripts/pll/read_rtt.py --seconds 3 --output build/rtt.log

# 待初始化结束、无故障后，启动原有 0.10 A 编码器电流控制并采样
python3 scripts/pll/capture_board.py --start-encoder --output build/shadow

# 后续仅采样，不修改控制方式
python3 scripts/pll/capture_board.py --output build/shadow_again

# 停车并核对硬件寄存器
python3 scripts/pll/capture_board.py --stop
python3 scripts/pll/board_status.py
```

`--stop` 在高速环运行时将故障锁存并关闭输出；高速环本来就停止的待机状态，可能只是留下未消费的停止请求，因此总要查看实际 MOTOR_EN/MOE，而不是仅看脚本“Stop requested”文字。停止后不应直接写 `fault=0` 或 `active=1` 来继续，正常重新初始化需要复位。

诊断工具用 GDB **离线**读取 ELF 的符号/字段偏移，通过 Tcl 读写运行中内存，不在转动时用断点暂停 MCU。暂停 CPU 时硬件 PWM 可能保持运行，会破坏时间基准，也可能让驱动一直保持某个输出。

采集脚本在写 RAM 前逐块比较 Flash 与相应 BIN 的整个有效镜像，保持 MCU 运行。仍需保证 ELF 与 BIN 来自同一次构建，并保留正式烧录 verify 和哈希记录。早期采集只检查前 512 字节向量表，交付工具已加强为完整镜像比较。

`--request-switch` 会发出有限时长接管请求。本次实机不满足条件，**没有执行此命令接管**。只有后续已看到足够长的正常映射旁路数据、误差达标且编码器 FOC 稳定时才使用。暂时不要打开 `PLL_AUTO_RUN_ENCODER` 或做无编码器启动。

### 怎样看 RTT

`PLLRelease` 每约 100 ms 输出一行估计速度、相对编码器的角度误差、锁定、接管、故障、周期与样本计数。速度字段为 mrad/s、角度误差为 mrad。`seq` 通常每行增加约 2000，`dt_us` 正常约 50；参考速度另外在采集 CSV 中查看。

RTT 在任务上下文输出，使用非阻塞 SKIP 模式；缓冲满时丢日志，不等待主机。只短暂关中断读取少量状态，再进行格式化，避免在 20 kHz ISR 内 `printf`。SEGGER 源文件来自你已有的另一个工程，保留原许可头。

采集使用 512×16 个 float 的 RAM 缓冲，大约 32 KiB，10 倍降采样后约 0.256 s 一次。写满后冻结，下载的 CSV 是这一段一致的记录；JSON 与 `board_status.py` 的字段则按顺序读取，不是同一瞬间的原子快照。

## 9. 为什么实机未通过，接下来怎样排查

当前证据不能确定唯一根因。先恢复可以重复启动、稳定旋转的**编码器 FOC 基线**，然后按下面顺序排查：

1. 核对三相功率输出顺序、两路分流电阻实际对应相位、ADC 零点/增益/符号；已知小电流注入时逐一确认，不能通过随意调 R/L 掩盖映射错误。
2. 核对 AS5600 机械安装、方向与电角度对齐结果。静态对齐应可重复，q 轴电流应产生预期转矩；最终 0.10 A 启动没有重复得到早期的稳定旋转，这是首要问题。
3. 用示波器或定时器调试引脚确认 PWM、ADC 采样和比较值装载的关系；核对死区、驱动极性、采样放大器是否在正确窗口稳定。
4. 测实际 R/L 并判断单位、线间与相值换算；确定模型假设是否适合该电机。验证足够信噪比的反电势后才调整观测器参数。
5. 较长记录多个稳定速度、正反转和负载变化下的角度误差；分别统计固定偏差、抖动、内部失锁、周期遗漏和电流。0.256 s 单窗口不足以覆盖运行工况。
6. 达到旁路条件后短时接管，验证丢失观测量、故障与停车；再设计电压/电流受限的开环启动、速度门槛和角度平滑交接。最后才验证移除编码器后的完整启动与运行。

在此之前，增大电流目标、电流积分限幅或降低判定门槛，都不能把未验证系统变成可靠无感 FOC。本次恢复了原来的 PI 积分限幅 0.3 V，也没有通过人为调整参考角度来消除统计误差。
